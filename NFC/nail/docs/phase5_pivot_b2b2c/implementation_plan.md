# Phase 5: B2B2Cモデルへの転換 (サロン提供型サービス)

## 概要
アプリの提供形態を「サロンが顧客にNFCタグ付ネイルを提供する」モデルに合わせ、システム構成を再定義します。

- **Salon (管理者)**: NFCタグへの書き込み、顧客管理を担当。
- **User (顧客)**: 自身のプロフィール編集、公開ページのデザイン管理を担当。

## Architecture Changes (アーキテクチャ変更)

### 1. ユーザーロールの導入
現在は全ユーザーが「プロフィール編集」も「タグ書き込み」もできてしまいます。これを権限分けします。

- **DB変更**: `User` モデルに `role` カラムを追加 (`USER` | `ADMIN`)。
    - `ADMIN`: すべての機能にアクセス可能 (特に `/admin` のタグライター)。
    - `USER`: `/app/profile` (編集) のみアクセス可能。`/admin` は使用不可。

### 2. サロン向け管理機能 (NFC Writer)
現在の「タグライター機能」を、サロンスタッフが使いやすい形に特化させます。

- **機能**: "自分のプロフィールを書く" のではなく、"指定したユーザーのURLを書く" 形に変更。
- **UI**: ユーザー検索機能、または「お客様の公開ページURL」を直接入力して書き込むモードをメインにする。

### 3. オペレーションフローの整備
サロンでの接客フローに合わせた動線を検討します。

**想定フロー:**
1.  お客様来店・施術。
2.  サロンスタッフがNFCタグをネイルに埋め込む。
3.  **[今回実装]** スタッフが管理画面 (`/admin`) を開き、お客様のプロフィールURL (例: `/u/customer-A`) を入力。
4.  スタッフがお客様のネイルにスマホをかざして書き込み完了。
5.  お客様は自分のスマホで `/u/customer-A` にアクセス (QRコード等?) し、ログインしてプロフィールを自由に編集。

## Proposed Changes (変更計画)

### Database
#### [MODIFY] `schema.prisma`
- `User` モデルに `role` Enum を追加 (Default: `USER`)。

### Middleware / Auth
#### [MODIFY] `src/middleware.ts` (またはレイアウト)
- `/admin` 以下のルートを `ADMIN` ロールを持つユーザーのみに制限。

### UI Components
#### [MODIFY] `src/app/admin/page.tsx` (Tag Writer)
- 「自分のプロフィールを書き込む」ボタンに加え、「任意のURLを書き込む」機能を強化。
- ※現在は「Any URL」モードがありますが、これをデフォルトにするか、使いやすくする。

## Verification Plan (検証計画)

### Role Testing
- `ADMIN` ユーザーのみがライター画面を開けることを確認。
- `USER` ユーザーはプロフィール編集のみできることを確認。

### Tag Writing Flow
- 管理者が任意のURL (お客様のページ) をタグに書き込めるか実機検証。
