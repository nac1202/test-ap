# 公式避難所データの統合 Walkthrough

## 実施内容と検証
- `NearbyShelters.tsx` と `gsiShelterService.ts` に実装した国土地理院(GSI)データの統合ロジックの動作検証を実施しました。
- ブラウザを使用した検証時、国土地理院のタイル取得APIがズームレベル15 (Z=15) において 404 エラーを返していることを発見しました。これはGSIの「指定緊急避難場所データ (skhb)」が **ズームレベル10 (Z=10)** で提供される仕様であるためでした。
- そのため、取得時のズームレベルを適切に `ZOOM_LEVEL = 10` に修正しました。
- Z=10 の1タイルには約30km四方の広域データ（約12,000件）が含まれます。モバイル環境等で大量のデータをフロントエンドで処理する負荷を軽減させるため、**取得したタイルデータの中から現在地の「5km圏内」の避難所のみを抽出（フィルタリング）** してマップ一覧に引き渡すロジックを追加実装しました。

## 実装・修正された機能
1. **国土地理院データの取得最適化**: `Z=10` のセンタータイルのみを取得。
2. **クライアント側フィルタリング**: 軽量化のため、取得後即座に「現在地から半径5km以内」の避難所に限定 (Haversine距離算出)。
3. **データ統合と重複排除**: GSIデータとGoogle Placesからの検索結果を統合し、50m以内の近接候補は公式データを優先して重複を削除。
4. **UIへのバッジ表示**: 公式データ由来のものには `ShieldCheck` アイコンとともに「指定避難所」という分かりやすいバッジが付与されます。

## 検証結果
- 全てのTypeScriptのビルドテストをクリア。
- 実際のローカルサーバー（`http://localhost:3000/shelter`）にて統合された検索フローがエラーなく正常に作動することを確認しました。
