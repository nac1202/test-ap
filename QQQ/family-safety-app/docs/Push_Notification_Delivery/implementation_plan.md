# プッシュ通知配信サーバー（Web Push機能）の実装計画

ユーザーがブラウザ（PWA）を閉じている状態や、ホーム画面に戻っている状態でも、スマホの画面に直接災害アラートを届けるための「本格的なプッシュ通知配信基盤」を構築する計画です。

今回はFirebaseなどに依存せず、既存の環境（Next.js + サービスワーカー + Supabase）を活かす標準的な **Web Push API** を用いたアプローチを提案します。

## 実装ステップ

### 1. VAPIDキー（暗号鍵）の生成と設定
*   **内容**: セキュアなプッシュ通知を送るために必要な公開鍵・秘密鍵（VAPID Keys）を `web-push` ライブラリを用いて生成します。
*   **作業**: アプリの環境変数（`.env`）にVAPIDキーを登録します。

### 2. 購読情報の保存先（Supabase DB）の構築
*   **内容**: ユーザーのブラウザ固有の「通知の送り先（PushSubscription）」と、先ほど作った「どの通知を受け取るかのON/OFF設定」を紐づけて保存するデータベーステーブル `push_subscriptions` をSupabaseに作成します。

### 3. フロントエンドの連携（購読処理）
*   **内容**: 先ほど作成した「プッシュ通知設定画面」の裏側に、ブラウザの通知許可（ポップアップ）を求める処理を組み込みます。
*   **作業**: 許可された場合、Supabaseへプッシュ通知先の情報と設定内容を送信（Subscribe）するAPIルート `/api/push/subscribe` を作成します。

### 4. サービスワーカー（Service Worker）の拡張
*   **内容**: バックエンドから送られてきたプッシュ・メッセージをスマホのバックグラウンドで見張るプログラム（ワーカー）を記述します。
*   **作業**: `next-pwa` の設定を拡張し、受信した通知をスマホのシステム通知として画面上にポップアップ表示するコードを書きます。

### 5. 通知テスト用の配信サーバー機能（API）
*   **内容**: 実際に災害が発生したと仮定して、対象ユーザーに通知を飛ばすバックエンドの配信プログラムを作ります。
*   **作業**: `/api/push/send-alert` のようなテスト用APIを作成。例えば「緊急地震速報の通知をONにしているユーザー全員」をDBから検索し、`web-push` を使って一斉に通知を送る処理を実装します。

## ユーザー確認事項
*   **iOS (iPhone) の制約について**: iPhone（Safari）でWebプッシュ通知を受け取るには、**「OSバージョンが iOS 16.4 以上であること」**、かつ**「ユーザーがこのアプリをホーム画面に追加（PWAとしてインストール）していること」**がAppleの仕様上必須となります（AndroidやPCのChrome等はインストール不要で可能です）。
*   本番環境（Vercel）で動かすためには環境変数（VAPIDキー等）のセットアップが必要になります。
