# 家族グループ機能 実装計画

## 目標
ユーザーが家族などの小規模グループを作成し、専用の招待リンク・コードを通じて他のメンバーを招待・参加できるようにする。これにより、アプリ内の「安否ステータス」や「位置情報」をグループ内で安全に共有可能にする。

## User Review Required
> [!IMPORTANT]
> **バックエンド（BaaS）の選定について**
> この機能を実装するためには、ユーザーの認証機能とデータをクラウドに保存するデータベースが必要です。どちらのバックエンドサービスを採用するか、ご希望を教えてください。（とくにこだわりがなければ、Next.js と相性の良い **Supabase** を推奨します）
> 
> - **候補A: Supabase (推奨)**
>   - RDB (PostgreSQL) を使用するため、ユーザー・グループ・所属メンバーというリレーション（関係性）の管理が非常に容易。
> - **候補B: Firebase**
>   - NoSQL (Firestore) を使用。リアルタイム同期は強力だが、グループ招待リンクなどのリレーショナルな実装設計に少し工夫が必要。

## データモデル設計案 (Supabaseの場合)
- **`users` テーブル**
  - `id` (Authと紐付け), `display_name`, `avatar_url`
- **`family_groups` テーブル**
  - `id`, `name` (例: "田中家"), `invite_code` (招待リンク用ランダム文字列)
- **`group_members` テーブル**
  - `group_id`, `user_id`, `role` (admin/member)
- **`safety_status` テーブル** (既存のローカル安否をクラウド化)
  - `user_id`, `status` (安全/負傷/避難中など), `message`, `lat`, `lng`, `updated_at`

## 提案する実装ステップ
1. **バックエンドの初期化**: 採用したBaaSのプロジェクトを作成し、APIキーを環境変数に設定・SDKを導入する。
2. **認証システム**: ユーザーがアカウントを作成できるログイン画面 (`/login`) を実装。
3. **グループ管理機能**: ログイン後のダッシュボード (`/settings` 等) で「グループ作成」や「招待リンクのコピー」ができるUIを作成する。
4. **招待参加システム**: `/invite/[code]` のような動的ルートを作成し、アクセスしたユーザーがグループに参加する処理を実装。
5. **既存機能のクラウド化**: `useFamilyLocation` フックなどを書き換え、モックデータやLocal StorageからバックエンドのDBを直接参照（またはリアルタイム購読）するように変更。

## 検証計画
- ローカル環境で2つのブラウザ（またはシークレットウィンドウ）を開き、「Aさんがグループを作成し招待リンクを発行 -> Bさんがそのリンクを踏んでログイン＆参加」というフローが正常に完了するかテストする。
- マップ上にAさんとBさんの位置情報が共有されるか確認する。

## フェーズ2 (今回実装): グループ作成・招待機能
本日から着手する「家族グループの作成」と「招待」に特化した機能の設計と実装手順です。

### 1. グループ管理画面 (`/group`) の作成
ユーザーが所属するグループの状況を確認できる専用画面を作成します。
- **未所属の場合**: 「新しいグループを作成する」ボタンと、「招待コードを入力して参加する」フォームを配置します。
- **所属済の場合**: グループ名、現在の参加メンバー一覧、そして「招待リンク / 招待コード」を表示します。

### 2. グループ作成ロジックの実装
ユーザーが「グループを作成」を押した時の動作：
- `family_groups` テーブルに新しいレコードを挿入。この際、ランダムな英数字6文字などの `invite_code` を自動生成します。
- `group_members` テーブルに、作成者自身を `role: 'admin'` として登録します。

### 3. グループ招待・参加ロジックの実装
- 管理画面上で発行された `invite_code` または招待URL (`/invite/[code]`) を他の人（家族）へ共有します。
- URLを踏んだ人（またはコードを入力した人）のユーザーID（`auth.user.id`）を、対象の `group_members` に追加する処理を走らせます。
- 参加が完了したら、自分の画面（`/group` や `/map`）に他の家族が表示されるようになります。

### これから行うこと
1. **`/group` ページのUI作成** と、そこへアクセスするためのナビゲーション追加（プロフィール画面などから遷移）。
2. **SupabaseのDB操作処理（グループ作成・参加）** をコンポーネントまたはカスタムフック内に実装。
3. 機能が完了次第、ご自身のブラウザでテストを実施していただきます。

## フェーズ3 (今回実装): 安否・位置情報のクラウド連携
フェーズ2で作成したグループ情報（招待・参加）を活用し、これまでの「デバイス内だけのテストデータ」から「家族とリアルタイムで共有できるデータ」へ移行します。

### 1. 安否送信機能の改修 (`StatusForm.tsx`)
- ユーザーが「無事/SOS/不明」を選んで送信した際、現在は `alert` が出るだけのモックになっています。
- これを Supabase の `safety_status` テーブルへ `UPSERT`（INSERTまたはUPDATE）するように改修します。
- 一緒に現在地（緯度・経度）も取得して送信できるようにします。

### 2. データ取得フックの改修 (`useFamilyLocation.ts`)
- これまで自分とダミーの家族1名の固定データを作成していましたが、このフックを Supabase連携型 に書き換えます。
- ユーザーが所属しているグループのメンバーID一覧を取得。
- そのメンバーIDを元に `safety_status` テーブルから最新の位置情報と安否ステータスを取得します。

### 3. マップと安否一覧画面への反映 (`/safety/page.tsx`, `/map/page.tsx`)
- バックエンドから取得した実際の家族のステータス情報（メッセージや更新日時）を画面にリスト表示します。
- マップ画面上のピンも、この新しいデータソースから表示されるようになります。（※UIコンポーネント自体はそのまま活用し、流し込むデータを差し替えます）

### これから行うこと
1. `StatusForm.tsx` の送信ロジックを Supabase 向けに実装。
2. `useFamilyLocation.ts` のモックデータを Supabase の `select` 処理に置き換え。
3. `/safety/page.tsx` に他メンバーの安否状況を表示するUIを追加。
