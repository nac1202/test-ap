## 手動E2Eで見つかった不一致と修正（一覧の省略防止）
- 事象: 「要注意案件を教えて」で、参照チップは2件（ベータ・ガンマ）だが回答本文はベータ案件のみ。
- 原因: 検索サービスは2件を正しく取得していた。資料の見出しが「要注意・遅延の案件」で、ガンマの状態は「遅延」だったため、AIが状態「要注意」の1件だけを本文に書いた（AIによる省略）。
- 要注意案件の定義（維持）: 状態が `warning`（要注意）または `delayed`（遅延）。ガンマ案件は状態が「遅延」のため対象（期限超過だからではない）。検索結果は2件のまま。
- 修正:
  1. 資料に「この資料には○件の該当があります。省略せず、すべて回答本文に列挙してください。状態が異なる項目（例：要注意と遅延）も含めてください」を付与（一覧系のみ。件数・詳細・該当なしには付けない）。
  2. 見出しを「要注意案件（状態が『要注意』または『遅延』のもの。『遅延』も要注意案件として扱う）」に変更。
  3. instructions に「一覧は全件を省略せず列挙。状態や種類で絞り込まない。件数は資料と一致させる」を追加。
  4. バックエンドは、列挙対象件数（`listed`）・`references` 件数・資料内の「・」行数が一致することをテストで保証（回答本文の機械解析は行わない）。
- 追加テスト: `test_31`（複数件の要注意案件が context / references / OpenAIへの入力のすべてに入る。期限・進行中・お知らせでも件数一致）。
