# Step 4C: 実E5モデル配備・検索品質評価 実装計画

## 目標
ローカル実行用の実際の埋め込みモデル (`intfloat/multilingual-e5-small`) を配置し、Mockではなく実モデルによる自然言語（日本語）検索機能の動作と品質を評価します。本ステップではLLMによる回答生成は行わず、FAISSでのベクトル検索の正確性と安全性を検証します。

## 1. モデル準備・配置方式
- プログラム本体（`demo_search.py` や各種検索ロジック）からは一切の自動ダウンロードを行いません。
- 管理者専用のセットアップスクリプト `scripts/setup_model.py` を新規作成します。このスクリプトは明示的に実行された時のみ、Hugging Face Hubから対象モデルをダウンロードし、許可ディレクトリ (`data/models/intfloat--multilingual-e5-small`) に配置します。
- ダウンロード時にモデルカード、ライセンス情報（LICENSEファイル等）、リビジョン情報、ファイルハッシュを取得・保存します。
- モデルディレクトリは `.gitignore` の対象とし、Git管理から除外します。

## 2. 実モデルの安全な読み込み
- `LocalSentenceTransformerProvider` を拡張し、`local_files_only=True` および `trust_remote_code=False` を徹底します。
- アプリケーション起動時にモデルディレクトリが存在しない場合は、「ローカル埋め込みモデルが配置されていないため、検索を実行できません」という日本語エラーを送出し、フェイルセーフとして動作を停止します（`ALLOW_MOCK_EMBEDDING=true`時を除く）。
- 読み込み後、モデルの出力次元（E5-smallの場合は384）を自動で実測し検証します。
- 実行時にCLI等へ「実モデル使用中」であることを明示します。

## 3. E5入力形式の分離と正規化
- E5モデル固有の要件に従い、入力文字列に対しプレフィックス（`query: `, `passage: `）を確実に付与します。
- 重複付与（`query: query: ...`）を防止するロジックを実装します。
- 空文字、長文、改行を含む日本語、バッチ処理に対する埋め込み生成をテストし、FAISS向けにL2正規化が正しく行われていることをアサーションで確認します。

## 4. 品質評価データの拡充 (`evaluate_search.py`)
自然な日本語によるクエリを評価スクリプトに追加します。
例：
- 「経営者に見せる資料では最初に何を提示すればよいですか」
- 「スライドに色を何種類も使うと何が問題ですか」
- 「表ではなくグラフを使うべきなのはどのような場合ですか」

これらに加え、同義語・言い換え、否定表現、無関係な質問（誤ヒットの検証）、曖昧な質問、長文・短文を含むデータセットを整備します。

## 5. 比較評価の実施
`evaluate_search.py` を用いて、以下の方式ごとに Recall@1/3/5, MRR, 誤ヒット数, 平均・最大検索時間を計測します。
- LIKE検索
- FTS5 trigram検索
- Mock Vector / Mock Hybrid
- 実E5 Vector / 実E5 Hybrid

Mock環境と実E5環境の結果を明確に分離し、Step 4C完了報告に記載します。

## 6. モデル変更とstale（旧データ）管理
- DBのチャンク（Embedding）には使用したモデルID（`embedding_model_id`）を記録します。
- Mockで生成されたEmbeddingと、実E5で生成されたEmbeddingを分離するため、実E5への切り替え時には「Mockデータによって構築されたFAISSインデックス」および「既存のベクトルデータ」をstale（無効）化、あるいは再構築するロジックを実装します。
- モデル変更後に古いベクトルが検索結果に混入しないことを自動テスト（`test_stale_embeddings.py`等）で確認します。

## 7. 外部通信の実測確認
- モデルセットアップスクリプト実行時：接続先（HF Hub）、ハッシュ、ライセンスの取得を明記します。
- 通常実行時：`socket` レベルでのパッチングを用いて、Hugging Face APIやLLM API等への不正な外部接続が試行されていないことをテストで検証します。

## 8. CLIデモ (`demo_search.py`)
デモスクリプトにおいて `--embedding real` フラグ等を使用可能とし、実E5での検索が実行できるようにします。
出力要件：
- モデルID、リビジョン、次元数
- Keyword / Vector / Hybrid の各順位
- 検索時間、除外件数
- ローカル絶対パスは隠蔽し、ファイル名やIDのみを表示します。
