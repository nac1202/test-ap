# くりぷとくん Phase 5: 資産推移の半永久記録と時間足変更システム 実装計画

## 概要 (Goal)
アプリ上の「総合評価額 推移グラフ」の表示期間を、従来の15分更新（過去24時間限定）から、「15分」「1時間」「4時間」「日足」の各時間足へ自由に切り替えられる本格的なプロ仕様チャートへ進化させます。合わせて、APIサーバーの履歴保存アルゴリズムを半永久的（数年分）の蓄積に対応させます。

## Proposed Changes

### バックエンド API・通信層
#### [MODIFY] `api_server.py`
1. **履歴データの無期限化**: 現状 96件（24時間分）を超えると最も古いデータを削除（`pop`）しているロジックを廃止し、データを継続的に蓄積するように変更します。
2. **タイムスタンプの拡張**: これまでは `HH:MM`（例: 15:30）の時刻のみで記録していましたが、「日足」対応のため `YYYY-MM-DD HH:MM`（例: 2026-04-17 15:30）のフル日時に形式を変更します。
   - ※既存のセーブデータ（HH:MMのみ）を読み込んだ際は、自動的に本日の日付を補完する互換性対応（マイグレーション）を挟みます。
3. **ルーティングの大幅軽量化**: 履歴データが数千・数万件に膨れ上がった際、5秒ごとの定期通信で毎回全データを送信するとアプリが重くなる（フリーズする）ため、`/api/status`からは履歴データを外し、新たに履歴専用の取得APIである `/api/history` エンドポイントを新設します。

### フロントエンド UI層
#### [MODIFY] `dashboard/index.html`
1. **切り替えボタンの設置**: チャートの上に、時間足を切り替えるためのトグルボタン枠（`[15分] [1時間] [4時間] [1日]`）を追加します。

#### [MODIFY] `dashboard/app.js`
1. **非同期履歴フェッチ**: 履歴データは5秒ループとは別に、1分に1回（あるいはタブ表示時のみ）取得するよう通信を分離し、巨大データでもサクサク動くように最適化します。
2. **リサンプリング（データ間引き）処理**: 取得した膨大な「15分ごと」の点群データ（データベース）を、ユーザーが選択した時間足に合わせてJS内でリアルタイムに間引き・圧縮計算し（例えば1時間足ならその1時間内の最後の点だけを抽出する等）、グラフのX軸・Y軸を瞬時に再描画するアルゴリズムを実装します。

## Verification Plan
1. バックエンドシステムが古いHH:MM形式のデータを破壊することなくYYYY-MM-DD形式へと正しく引き継いでいるかを確認します。
2. ダッシュボード上のボタン（15分 / 1時間 / 4時間 / 1日）をクリックした際に、正しくX軸のメモリとグラフの粗さが変化することを確認します。（初期はデータが少ないため、日足等は点が数個のみの表示となります）
