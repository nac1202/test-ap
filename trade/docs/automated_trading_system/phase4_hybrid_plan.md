# くりぷとくん Phase 4: 究極ハイブリッド同時稼働（聖杯）システム 実装計画

## 概要 (Goal Description)
相場の「上昇」と「下落」の両方の波を24時間同時に捉え続けるため、現物口座（資金10万円）と証拠金口座（資金10万円）を完全に独立した2つの「AIエンジン」として同時稼働させるアーキテクチャへとシステムを根本から再構築します。
現物チームは上昇相場でのみ利益を出し、FX（空売り）チームは下落相場でのみ利益を出すという、お互いの弱点を完全に補い合う究極のフルオート自律システムを目指します。

## Proposed Changes

### バックエンド API・通信層
#### [MODIFY] `fetchers/market_data.py`
- これまでの単一口座通信から、毎回のループで「現物の資産残高（日本円・BTC）」と「証拠金の残高・建玉一覧」の両方を独立して同時に取得できるよう通信処理を統合拡張します。

### AI ロジック・実行層
#### [MODIFY] `strategies/decision_maker.py`
- 1つのシステムの中で、以下2つのエンジンをパラレル（並列）で稼働させ、毎回2つの独立したシグナルを発行する構造へと改修します。
  1. **現物買い専属（Spot）エンジン**: RSIが低い底値で買い、高い天井で利確売りする「上昇トレンド特化型」。
  2. **空売り専属（Short）エンジン**: RSIが高い天井で空売り（Short）を仕掛け、低い底値で買い戻す「下落トレンド特化型」。

#### [MODIFY] `execution/order_manager.py`
- オーダーの処理窓口を `execute_spot_signal`（現物用）と `execute_margin_signal`（FX用）の2つに完全に物理分割します。
- これにより、「FX用の証拠金が現物の購入に使われてしまう」といった資金混同バグを100%防ぎます。

### フロントエンド UI層
#### [MODIFY] `dashboard/index.html` および `dashboard/app.js`
- 画面上部の資産パネルを「現物運用（Spot）セクション🟢」と「証拠金運用（FX）セクション🔴」の2つのカードに左右分割して配置します。
- 双方の資金状況（現物の現金残高やBTC保有量、およびFX側の証拠金維持率や空売り建玉）が一つの巨大なコントロールルームのようにひと目でハッキリと全貌を把握できる、司令塔専用ダッシュボードへと完全リニューアルします。

## Verification Plan
1. プログラム再起動後、GMOコインから「現物用10万円」と「FX用10万円」の両方の合計残高が混ざらずにエラーなく取得できているか確認する。
2. ダッシュボードのパネルがきれいに2つの領域に分割表示され、正しくデータがマッピングされていることを確認する。
3. 問題なく両方のシステムが別々のシグナルを待機できるか（またはテスト注文が行えるか）を検証し完了とする。
