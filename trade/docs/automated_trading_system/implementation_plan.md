# 仮想通貨ハイブリッド自動トレードシステム 実装計画

本プロジェクトは、国内の取引所（GMOコイン）を利用し、テクニカル分析とファンダメンタル情報を融合させて24時間自動で取引を行うシステムを構築します。

## 背景と技術スタックの選定理由（オススメの構成）

ご経験のある「仮想通貨」をターゲットにすることを強く推奨します。
メインアカウントの資金リスクを避けるため、そして初期投資額10万円で安全にシステムを運用するため、**GMOコイン**をボット専用口座として新規開設・運用する方針をとります。

### 採用するシステム構成
* **稼働先の取引所**: **GMOコイン** (ボット専用として独立させやすく、Maker手数料が無料/マイナスになるなどAPI自動売買に非常に有利です。BTC/JPYペアに特化します)
* **開発言語**: **Python** (データ分析、AI処理、API通信のすべてにおいて業界標準であり、最も情報が多いため)
* **データ取得と発注**: **CCXTライブラリ** (世界中の取引所APIを共通のコードで操作できる強力なツール)
* **テクニカル分析**: **ピュアPython実装** (Python最新環境との互換性とシステムの軽量化を重視し、重い外部ライブラリに依存せずMACDやRSIを瞬時に計算します)
* **ファンダメンタル分析**: 
  1. **Fear & Greed Index API**: 仮想通貨市場全体の「強気・弱気」の感情を数値で取得。
  2. **CryptoPanic API 等のニュースアグリゲーター**: 最新のニュース見出しを取得し、簡易的なセンチメント判定を付与。

---

## 決定事項
* 稼働先の取引所: **GMOコイン** (ボット専用口座)
* 取引区分: **フェーズ1として現物取引（Spot）**から開始。長期間安定稼働を確認後、フェーズ2でレバレッジ取引（暗号資産FX）を解禁して空売りを実装する段階的設計とする。
* API設定: 発行するAPIキーには「送金・出金権限」を付与せず、「トレード機能」と「口座照会連携」のみを許可する。
* プログラム内の安全装置: 投資額10万円を上限とするロジックを組み込み、それ以上の資金を動かさない。（実装時対応）

## 実装ステップと予定（アーキテクチャ）

### [Component 1: 環境構築と基盤整備]
* `config/`: 取引所のAPIキーやシステムの共通設定を管理するモジュール。
* `utils/logger.py`: 24時間稼働させるため、動作状況やエラーを記録するログ機能。

### [Component 2: データ取得モジュール]
* `fetchers/market_data.py`: GMOコインからリアルタイムの価格や過去のローソク足データを取得（CCXT利用）。
* `fetchers/fundamental_data.py`: Fear & Greed Indexや最新ニュースのデータを取得するスクリプト。

### [Component 3: 分析・戦略モジュール (AI・ロジック部)]
* `strategies/technical.py`: 取得した価格データをもとに、複数のテクニカルサインを生成。
* `strategies/fundamental.py`: ニュースのセンチメント分析などファンダメンタル指標からスコアを算出。
* `strategies/decision_maker.py`: テクニカルとファンダメンタルの両方のスコアを総合し、「買い」「売り」「待機」の最終判定を下すコアロジック。

### [Component 4: 実行モジュール]
* `execution/order_manager.py`: 取引所への実際の注文送信、注文キャンセル、残高確認を行う機能。
* `main.py`: 上記すべてのコンポーネントを統合し、一定間隔（例：5分ごと）でループ実行するコアプログラム。

### [Component 5: 洗練された専用Webダッシュボード (フロントエンドUI)]
* **デザイン方針**: ダークモード基調でグラスモーフィズム（半透明グラデーション）を取り入れた、プレミアムでサイバー感のある動的デザイン。最高水準のUX。
* `api_server.py`: ボットからリアルタイムデータ（残高、分析状況、稼働状況）をダッシュボードへ配信する軽量APIシステム（Flaskベース）。
* `dashboard/`: ユーザーインターフェースの格納ディレクトリ（HTML, モダンCSS, JavaScript）。アニメーションやリアルタイム更新を搭載。

## Verification Plan
1. **結合テスト**: 取引所のAPIキーを設定後、テストモード（残高照会などの安全なAPI）で通信が成功するか確認する。
2. **データ取得・ロジックテスト**: 実相場データを用いて、予期した通りに売買指示（シグナル）が生成されるかをログで確認する。（この段階では実際の発注は行わない紙上トレード）
3. **本番稼働検証**: 問題なければ、非常に小さなロット（最低取引単位）で実運用を行い、正常に約定するかを監視する。
