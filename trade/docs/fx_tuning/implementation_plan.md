# 資金20万円を活用する「FX専用予算の分離」と「エラースパム防止」

ユーザー様からの「証拠金維持率の危険性」に対する的確なご指摘をふまえ、**証拠金維持率を安全水準に保ちつつ最大効率で運用する**ための最適なシステム改修プランです。

## 🎯 予算分離による「2発まで限定」の安全ナンピン戦略
FX（レバレッジ）運用において、証拠金20万円に対して3発フル（必要証拠金18万円）で撃つのは、少しの逆行でロスカットに触れるため極めて危険です。
しかし、ダッシュボード上に「FX専用の運用限度額」を新設することで、**「最大2発（0.02BTC）までで絶対にストップさせる」**というコントロールが可能になります。

### 安全性の計算（一例）
*   **ダッシュボード設定**: `FX専用限度額を「20万円」`、`フルポジション（上限）を「80% (16万円)」`とする。
*   **1発目**: 0.01 BTC（名目12万円相当 / 必要証拠金6万円）をショート。
*   **2発目**: さらに0.01 BTC追加。累計0.02 BTC（名目24万円相当 / 必要証拠金12万円）。
*   **ストップ！**: ここでシステムは「現在の建玉(名目24万)が、設定上限(20万×80%=16万)を超えた」と判断し、3発目は一切撃たなくなります！

これにより、残りの証拠金8万円分が「クッション（猶予）」として残ります。BTC価格設定上、8万円の猶予があれば **ビットコインが今から一気に＋400万円（約33%）の歴史的大暴騰をしない限りロスカットされない** 非常に安全な防衛ラインが構築できます。

## 🛠️ プログラム変更計画

### 1️⃣ `dashboard/index.html` & `dashboard/app.js` の変更
- 「運用限度額 (最大予算目安)」の下に、「🔴 FX専用 運用限度額（証拠金目安）」という新しいスライダー（初期値20万円）を追加する。
- ユーザー様が自分でFXだけの最大予算を微調整できるように、API通信に `margin_trade_amount_limit` パラメーターを追加する。

### 2️⃣ `api_server.py` の変更
- 「証拠金不足」等のエラーが発生した場合、無限にリトライしてログを埋め尽くすのを防ぐため、強制的にクールダウンタイマーを起動させ連続発注をストップ（おやすみ）させる処理を `bg_updater` 内に追加する。

### 3️⃣ `strategies/decision_maker.py` の変更
- FXの「最大予算オーバー判定 (`is_margin_full`)」において、現物共通の限度額ではなく、新設した **`margin_trade_amount_limit`** を使用するようにロジックを分離する。
